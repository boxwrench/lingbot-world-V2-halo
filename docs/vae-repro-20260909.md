# Isolated Wan VAE decode — 2026-09-09

This is a real-VAE control, independent of the LingBot transformer. It uses
the pinned shared Wan VAE weights and the same 480×832-equivalent latent
geometry used by the cross-platform investigation.

## Command

```bash
python scripts/vae_repro.py \
  --model-dir "$MODEL_DIR" \
  --runs 3 \
  --latent-frames 4 \
  --latent-height 60 \
  --latent-width 104 \
  --out-json results/raw/vae/strix-gfx1151-480x832-aggregate.json
```

The runner wraps each `nn.Conv3d` only to record the actual input/weight
shapes and synchronized elapsed time. It does not alter padding, dtype,
layout, or module behavior.

The dominant actual VAE shape was:

```text
input  [1,96,4,480,832]
weight [96,96,3,3,3]
padding=(0,0,0)
```

It occurred 54 times across three decodes and consumed 29.686 s, or 37.72%
of measured Conv3d time. Other major groups were
`[1,192,4,240,416] × [192,192,3,3,3]` at 28.67% and
`[1,384,2,120,208] × [384,384,3,3,3]` at 14.27%.

The real decoder does not pass synthetic case B's depth-6 padded tensor to
every convolution. The most expensive high-resolution group is the depth-4
case above, while the synthetic B case remains useful because it exactly
matches the R9700 padded-shape hypothesis.

## Interpretation boundary

The decode is numerically viable on gfx1151 and the large unified-memory pool
comfortably accommodates the isolated VAE. Conv3d dominates the decode, but
this measurement alone is not a correctness-preserving optimization design;
solver selection and backend behavior must be characterized first.
