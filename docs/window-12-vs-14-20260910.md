# Persistent window A/B — 12 frames vs 14 frames (2026-09-10)

## Question

Are two additional recent latent frames worth the latency cost for persistent
world quality?

This was one bounded comparison. The only changed parameter was physical local
attention capacity. The 18-frame quality/reference mode and 12-frame accepted
interactive mode remain unchanged in the repository defaults.

## Configuration

```text
384×672 actual geometry
48×84 latent geometry
1008 tokens/frame
chunk_size=1
3 denoise: 999 → 899 → 702
exact deferred t=0 clean-KV commit
BF16 DiT, PyTorch fused SDPA
FP16 TAEHV taew2_1 presentation decoder
serial execution
sink_size=6
```

The same deterministic 40-action traversal was used for both unprofiled
timing runs:

```text
w,w,j,w,l,l,s,s,j,w,d,d,w,l,a,a,w,j,s,l,w,w,d,j,a,s,l,w,d,d,j,w,a,a,l,s,w,j,l,w
```

The runs included bootstrap plus 40 actions, reached repeated rollovers, and
completed 41 rows each. Primary timings were collected without video capture.
The existing 12-frame 161-frame capture from the same traversal was compared
with a new 14-frame 161-frame capture.

## Cache accounting

| Configuration | Sink | Recent | Current | Total K | Final global position |
|---|---:|---:|---:|---:|---:|
| 12-frame control, rolled | 6,048 | 5,040 | 1,008 | 12,096 | 41,328 |
| 14-frame candidate, rolled | 6,048 | 7,056 | 1,008 | 14,112 | 41,328 |

The 14-frame candidate filled at chunk 13 and began rolling at chunk 14. The
runtime reported the expected `6,048 + 7,056 + 1,008 = 14,112` tokens. Global
position advanced monotonically while local K remained bounded.

Steady allocations were approximately 17.98 GB allocated / 18.60 GB reserved
for 12 frames and 18.35 GB / 19.20 GB for 14 frames. RSS was approximately
3.57 GB in both runs.

## Quality and persistence

Both unprofiled runs were finite for all 41 rows. Both exercised forward
motion, long turns, reversals, strafing, and repeated local-window rollovers.
No frozen output, numerical collapse, or catastrophic scene replacement was
observed.

The matched 161-frame captures were 10.06 seconds at 16 fps. Early frames are
effectively the same; divergence becomes visible after the shorter window has
forgotten recent history. In late samples around frame indices 96–160, the
14-frame run more consistently retained a distinct right-hand shoreline/
structure and a stable tree-to-background relationship. The 12-frame run more
often substituted or blended that structure and showed greater texture/edge
variation. The main lake, tree, mountain geometry, and camera direction
remained coherent in both.

| Quality dimension | Observation |
|---|---|
| Geometry | Both preserve the main lake/tree/mountain scene; 14 better retains late shoreline structure. |
| Object persistence | 14 has steadier tree/shoreline relationships after rollover; 12 changes them more often. |
| Turns and reversals | Both respond to the scripted turns and reversals without freezing. |
| Revisits | 14 is more consistent in the late return/shoreline views; this was visual, not a formal pose-error score. |
| Texture | 14 shows less late texture/edge substitution; 12 is more variable. |
| Flicker | No catastrophic flicker; both have normal generative texture variation. |
| Drift | Both remain finite and coherent; 12 accumulates more visible late divergence. |
| Rollover | Both retain sink state and keep global position advancing with bounded local K. |

This is a visual comparison of separately generated sessions. Exact pixel
identity after the histories diverge is neither expected nor required.

## Decision

**BOTH MODES JUSTIFIED.** The 14-frame mode earns its extra cost: it provides a
visible but moderate persistence/texture improvement in late rolled views for
approximately `73 ms` more first-visible latency and `99 ms` more next-action
readiness. The 12-frame mode remains valuable because it is approximately
1.03 s first-visible when rolled and is the minimum-latency candidate.

Keep the current product roles:

```text
18 frames: quality/reference
12 frames: lowest-latency interactive
14 frames: higher-quality interactive option
```

No default was changed by this experiment.
