# R9700/gfx1201 MIOpen solver audit — 2026-09-09

This document records the live cross-architecture follow-up from the Strix
Halo experiment. It is intentionally limited to MIOpen solver selection for
the matched Conv3d reproducer; it does not modify the R9700 baseline or apply
a VAE optimization.

## Force/invocation test

Two bounded attempts were made to invoke GEMM without changing the model:

1. `MIOPEN_DEBUG_FIND_ONLY_SOLVER=GemmFwdRest` on B still ended with the
   direct-naive record and a 5.0362 s warm median in the Python reproducer.
2. `MIOpenDriver conv --solution GemmFwdRest` with batch size 1 reached
   solution ID 91, but the library returned:

   ```text
   The supplied solution id: GemmFwdRest is not applicable to the current problem
   ```

   It exited with status 3 before executing GEMM.

The raw driver log is
[`r9700-driver-force-gemm-B.log`](../results/raw/conv3d/r9700-driver-force-gemm-B.log).
This agrees with MIOpen's documented behavior: a valid but not-applicable
solver cannot be forced through `MIOPEN_DEBUG_FIND_ONLY_SOLVER`.

## Cross-platform interpretation

| Question | Evidence-based answer |
|---|---|
| Is `GemmFwdRest` absent on gfx1201? | No. It is present, works for A, and the driver assigns it solution ID 91. |
| Is it rejected for B/C/D on the old stack? | Yes. Required workspace `16,562,257,920` exceeds the logged ceiling `14,574,367,538`; MIOpen marks it not applicable. |
| Is direct naive the only viable old-stack candidate? | Yes, according to `SearchForAllSolutions` for each B/C/D block. |
| Can the standard old MIOpen API force GEMM anyway? | No, not for B in the tested state; the API still reports not applicable. |
| Does the same gfx1201 hardware run GEMM for B/C/D? | Yes, under the separate ROCm 7.14/MIOpen 3.5.2 environment. |
| Is this proven architecture-only? | No. The newer-stack control rules that out as the sole explanation. |
| Is the exact software component isolated? | Not yet; MIOpen policy/database, rocBLAS, and their interaction remain possible. |

The strongest current classification is **old-stack MIOpen workspace-gated
solver selection on gfx1201**, with a newer-stack fix or changed behavior. The
next useful bounded experiment is to identify whether the 7.2.1 workspace
ceiling can be changed safely or whether the old solver's workspace estimate
is inherently too large for this shape. A custom decomposition should wait
until that control is complete.
